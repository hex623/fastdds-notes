04 - 消息传递机制

来源: 2026-03-03 深度讲解
整理时间: 2026-03-17

核心概念

HEARTBEAT - 心跳消息

方向: Writer → Reader
作用: “我有这些数据，请确认”

包含字段:
- First Sequence Number: 最早可用数据序列号
- Last Sequence Number: 最新数据序列号
- Count: 心跳计数器（去重）

触发时机:
- 定期发送（默认 10 秒）
- 数据发送后触发
- 用于活性检测

ACKNACK - 确认/否定确认

方向: Reader → Writer
作用: “收到这些，缺这些，请重传”

结构:
- ACK: 确认收到（位图标记为1）
- NACK: 请求重传（位图标记为0）
- 位图结构: Base + Bitmap（每个bit表示一个序列号）

可靠传输交互流程

正常传输

Writer → Reader: DATA(Seq#1)
Writer → Reader: DATA(Seq#2)
Writer → Reader: DATA(Seq#4)
Writer → Reader: HEARTBEAT(First=1, Last=4)
Reader → Writer: ACKNACK(Base=1, Bitmap=1101)  // 缺 #3
Writer → Reader: DATA(Seq#3) [重传]
Reader → Writer: ACKNACK(Base=5, Bitmap=1)     // 全收到

位图解析示例

ACKNACK(Base=1, Bitmap=1101)

Base=1 表示从序列号1开始
Bitmap=1101 (二进制)
  - bit 0 (Seq#1): 1 = 已收到 ✓
  - bit 1 (Seq#2): 0 = 未收到 ✗ (请求重传 #2)
  - bit 2 (Seq#3): 1 = 已收到 ✓
  - bit 3 (Seq#4): 1 = 已收到 ✓

关键机制

1. 序列号去重

Reader 维护已接收序列号集合，丢弃重复数据。

2. 延迟 ACK

Reader 等待短暂时间（默认 50ms）后批量确认，减少 ACKNACK 频率。

3. NACK 抑制

防止 Reader 频繁发送 NACK 导致重传风暴：
- 指数退避: 重传间隔逐渐增加（1s → 2s → 4s…）
- NACK 合并: 批量请求缺失数据

4. 指数退避重传

第1次重传: 等待 1 秒
第2次重传: 等待 2 秒
第3次重传: 等待 4 秒
第4次重传: 等待 8 秒
...
最大间隔: 通常 30 秒

消息类型速查

消息类型 方向 作用 可靠通信
DATA W→R 传输用户数据 ✅
HEARTBEAT W→R 通知可用数据 ✅
ACKNACK R→W 确认/请求重传 ✅
GAP W→R 告知数据不可用 ✅
INFO_TS W→R 时间戳信息 ⚠️

GAP 消息

当 Writer 清理历史数据（History QoS），某些序列号不再可用时，发送 GAP 告知 Reader。

INFO_TS

携带数据的时间戳信息，用于时间同步和延迟测量。

可靠 vs 尽力而为对比

特性 RELIABLE BEST_EFFORT
确认机制 HEARTBEAT/ACKNACK 无
丢包处理 自动重传 丢弃
延迟 较高（确认开销） 较低
带宽 较高 较低
适用场景 关键数据 实时视频/音频
